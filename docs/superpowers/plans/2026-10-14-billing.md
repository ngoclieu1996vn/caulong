# Daily Billing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nhập chi phí theo ngày, lưu giờ từng người và tính đúng phần tiền sân theo giờ, cầu/trà theo đầu người.

**Architecture:** Tách helper người tham gia, logic tính tiền thuần, service document theo ngày và UI controller. `detail.js` chỉ truyền danh sách đã xác nhận và render số tiền; mỗi phần mới lỗi riêng, không làm hỏng check-in hiện có. Kế hoạch này có thể bàn giao độc lập trước phần trò chơi.

**Tech Stack:** HTML/CSS, JavaScript ES Modules, Firebase Modular SDK 13.0.0 CDN; Node test runner, Playwright và Firestore Emulator đang có chỉ dành phát triển.

**Spec:** `docs/superpowers/specs/2026-10-14-billing-and-team-games-design.md`, trọng tâm mục 1–5, 9–11.

**Execution:** Tự thực hiện trong phiên như cách đã chọn trước; một lượt review độc lập sau tích hợp. Theo chỉ dẫn người dùng, không sử dụng Git kể cả status/diff, không tạo worktree/commit/push/deploy. Ghi tiến độ bằng checklist và `.playwright/billing-progress.md`; không chạy helper quản lý kế hoạch có thao tác Git.

## File Structure và dữ liệu

- `js/participants.js`: chuẩn hóa danh sách và dấu vết phiên bản, dùng chung với trò chơi.
- `js/billing.js`: input/tổng chi phí/phân bổ đồng nguyên, không DOM/Firebase.
- `js/day-document-service.js`: primitive subscribe/transaction theo ngày dùng chung hai collection mới.
- `js/billing-service.js`: adapter collection `billing`.
- `js/billing-ui.js`, `css/billing.css`: form, giờ, dirty/stale/remote conflict và kết quả.
- Modify `js/detail.js`, `js/checkin-service.js`, `detail.html`, `firestore.rules`, `README.md`, `package.json`, `tests/verify.mjs`.
- Tests: `tests/participants.test.mjs`, `tests/billing.test.mjs`, `tests/day-documents.spec.mjs`, `tests/billing.spec.mjs`, mở rộng `tests/firestore.rules.test.mjs`.

`Participant = {id, version, name, memberId, type, gender, avatar}`; `gender` là `Nam`, `Nữ` hoặc null. Version timestamp có seconds/nanoseconds; helper hỗ trợ timestamp stub có toMillis trong test hiện có. Dấu vết nguồn là chuỗi chuẩn hóa ID/version sắp theo ID; có tùy chọn kèm giới tính cho trò chơi.

`BillingInput = {courtFee, shuttles:[{id,label,unitPrice,quantity}], tea:{quantity,unitPrice}, hours:[{id,version,halfHours}]}`. Đơn giá chưa nhập biểu diễn null; số lượng 0 cho phép đơn giá null và thành tiền 0.

`BillingResult = {courtTotal,shuttleTotal,teaTotal,total,allocations:[{id,version,halfHours,courtAmount,sharedAmount,amount}]}`. Document `billing/{date}` chứa `{schemaVersion:1,input,status:'draft'|'calculated',participants,sourceFingerprint,result:null|BillingResult,revision,updatedAt}`. Revision/server time do service ghi. Lưu bản nháp phải đặt result null.

## Task 2: Tính tổng và phân bổ tiền nguyên đồng

**Files:** Create `js/billing.js`, `tests/billing.test.mjs`; thêm file vào lệnh unit tests và `tests/verify.mjs`.

**Consumes:** Participant/rosterFingerprint từ Task 1.
**Produces:** `createBillingInput(participants): BillingInput` mặc định sân 220000, hai giá cầu 27000/25000 số lượng 0, trà 0/null, halfHours 4; `reconcileHours(input,participants): BillingInput` giữ giờ đúng id+version; `calculateTotals(input): {courtTotal,shuttleTotal,teaTotal,total}`; `calculateBill(input,participants): BillingResult`; `isBillingCurrent(document,participants): boolean`; `formatMoney(amount): string` dùng Intl vi-VN/VND.

- [ ] Viết test tính tiền với assertions sau:

  ```js
  // Bốn người a,b,c,d: halfHours 4,4,2,2; sân 220000;
  // cầu 2×27000 + 1×25000; trà 1×20000.
  assert.equal(result.total, 319000);
  assert.deepEqual(result.allocations.map(p => p.amount), [98083, 98083, 61417, 61417]);
  assert.equal(result.allocations.reduce((sum, p) => sum + p.amount, 0), 319000);
  ```

  Thêm assertions: chia 1đ cho a/b/c thì a nhận 1đ dù đảo thứ tự input; 0 giờ vẫn chia phần cầu/trà; tất cả 0 giờ + sân>0 thì throw; sân=0 và mọi giờ=0 vẫn chia được phần chung; không người thì throw khi tính nhưng tạo/lưu nháp được. Thiếu giá chỉ lỗi khi lượng>0; giá 0 được phép; reject số âm, NaN, vô hạn, lượng lẻ, tiền lẻ đồng và tổng vượt safe integer.
- [ ] Chạy `node --test tests/billing.test.mjs`; expected fail vì chưa có implementation.
- [ ] Implement chia sân và phần chung riêng bằng phép chia BigInt/remainder, đổi về Number sau kiểm tra giới hạn; tie-break theo ID. Giờ là số nguyên 0..48 nửa giờ. Không dùng số thực để phân phối đồng dư.
- [ ] Test reconcileHours đưa người mới/recheck về 4, giữ người không đổi; draft/khác roster trả isBillingCurrent=false. Chạy toàn bộ unit tests; expected pass. Ghi Task 2.
